# 统一工作室与任务中心实现方案

## 1. 方案目的

将剧本工作室、替换工作室、媒体工具和资源管理统一为同一个应用内的业务模块，消除“主应用 + 旧版 ShuoCanvas 子应用”的使用感知差异。

最终用户只需要理解两件事：

- 应用只有一套主题设置：浅色、深色、跟随系统。
- 应用只有一套任务管理：所有模块的任务都能持续运行、查看、取消、重试和追溯。

本方案先建立统一基础设施，再逐步迁移剧本和替换工作室，避免一次性重写导致已有功能回归。

## 2. 当前问题与证据

| 发现 | 证据 | 结论 |
| --- | --- | --- |
| 主应用有统一主题状态 | `Serpent/src/renderer/theme/ThemeProvider.tsx` | 可作为全局主题唯一来源 |
| 旧版工作室仍有独立主题预设 | `Serpent/src/renderer/shuocanvas-legacy/src/modules/settings/appearanceSettings.js` 中的 `dusk/dawn/day` | 需要降级为兼容映射，最终隐藏旧入口 |
| 剧本工作室通过旧版 CSS 和 DOM 工作区运行 | `Serpent/src/renderer/story-studio/LegacyStoryStudioWorkspace.tsx` | 当前仍是旧版挂载模式 |
| 替换工作室通过旧版桥接器运行 | `Serpent/src/renderer/replacement-studio/OriginalReplacementWorkspace.tsx` | 当前仍依赖旧版运行时和样式 |
| 任务面板已有剧本工作室局部实现 | `Serpent/src/renderer/story-studio/legacy-story-studio.css`、`LegacyStoryStudioWorkspace.tsx` | 可迁移为统一任务中心的工作室视图 |

## 3. 目标架构

```text
AppShell
├── 统一导航与页面生命周期
├── ThemeProvider（唯一主题状态源）
├── TaskCenterProvider（唯一任务状态源）
├── 资源管理模块
├── 剧本工作室模块
├── 替换工作室模块
└── 媒体工具模块
```

### 3.1 统一主题

- 保留 `light / dark / system` 三种主应用设置。
- `dusk / dawn / day` 仅作为旧数据兼容映射，不再作为用户可见的第二套主题入口。
- 所有模块只读取 `ThemeProvider` 暴露的解析主题和 `--ui-*` 令牌。
- 删除旧版主题对背景、文字、边框的固定颜色覆盖。
- 主题切换只改变视觉状态，不销毁工作室实例，也不取消运行中的任务。

### 3.2 统一任务中心

任务中心是公共服务和公共数据模型，不要求所有页面使用完全相同的布局。每个模块可以显示“当前模块任务”过滤视图，顶部全局入口可以显示“全部任务”。

统一任务状态：

```text
queued → running → succeeded
                 ├→ failed
                 ├→ cancelled
                 └→ interrupted
```

每条任务至少记录：

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一任务 ID |
| `module` | `story`、`replacement`、`media`、`assets` |
| `type` | 任务类型，例如剧本生成、人物检测 |
| `title` | 用户可读名称 |
| `status` | 排队、运行、成功、失败、取消、中断 |
| `progress` | 0 到 100 的总体进度 |
| `currentStage` | 当前阶段名称 |
| `stages` | 各阶段开始、结束、耗时和状态 |
| `createdAt/startedAt/finishedAt` | 生命周期时间 |
| `error` | 错误码、用户提示和技术详情 |
| `result` | 结果文件、项目 ID 或可恢复数据 |
| `cancelable/retryable` | 当前任务是否允许取消或重试 |

任务记录持久化到本地数据库或现有任务存储中。页面卸载只解除页面订阅，不调用任务取消；只有用户明确点击“取消任务”时才发送取消请求。

## 4. 用户界面方案

### 4.1 主应用布局

```text
┌─────────────────────────────────────────────┐
│ 顶部导航  模块切换       运行中任务 主题设置 │
├──────────────┬──────────────────────────────┤
│ 项目目录/资源 │ 当前模块工作区               │
│              │                              │
│              │                              │
└──────────────┴──────────────────────────────┘
```

- 左侧为项目目录或资源导航，宽度可拖拽并记忆。
- 右侧为模块主工作区，避免两侧大面积空白。
- 顶部任务入口显示运行中数量和失败数量。
- 任务中心支持右侧抽屉、底部面板和独立页面三种展示方式；默认使用右侧抽屉。

### 4.2 剧本工作室

- 保留剧本编辑、项目、分集、分镜等功能。
- 右侧显示统一任务中心的“剧本任务”过滤视图。
- 任务面板可切换“当前项目 / 全部剧本任务 / 全部模块任务”。
- 任务详情展示阶段进度、阶段耗时、失败原因、重试和取消操作。
- 切换到其他模块后任务继续运行，返回时恢复相同任务详情。

### 4.3 替换工作室

- 保留素材上传、人物检测、替换生成和结果预览。
- 将任务生命周期交给统一任务中心。
- 自动检测、逐帧分析、视频生成拆成可观察的阶段。
- 失败时显示明确原因，例如“未配置视觉模型”“关键帧路径无效”“模型返回格式错误”。

### 4.4 任务详情交互

- 运行中：显示阶段进度、已耗时、预计剩余时间（可计算时）。
- 成功：显示结果入口、总耗时和各阶段耗时。
- 失败：显示用户可理解的原因、技术详情折叠区和“重试”。
- 可取消：只对排队中或运行中且执行器支持取消的任务显示取消按钮。
- 已取消/中断：保留记录，不伪装为失败；支持删除记录或重新执行。

## 5. 分阶段实施计划

### 阶段一：统一基础设施

1. 建立 `TaskCenterProvider`、任务类型、状态机和持久化接口。
2. 将现有剧本任务适配到统一任务模型。
3. 增加全局任务入口和任务详情抽屉。
4. 明确页面切换与任务执行器解耦规则。

验收：切换页面不会取消剧本任务；刷新应用后任务记录可恢复；成功、失败、取消状态可区分。

### 阶段二：统一主题和应用外壳

1. 以 `ThemeProvider` 为唯一主题来源。
2. 隐藏旧版 `dusk/dawn/day` 用户入口，保留兼容读取和映射。
3. 把剧本、替换、媒体工具放入统一 `AppShell` 内容区。
4. 将任务中心抽屉挂在主应用层，而不是挂在某个工作室内部。

验收：四个模块主题切换一致；切换模块不出现独立黑底或第二套标题栏；任务抽屉可从任意模块打开。

### 阶段三：剧本工作室迁移

1. 抽离旧版剧本 API、项目数据和生成执行器。
2. 用 React 组件逐步替换旧版 DOM 工作区。
3. 复用业务数据，不再复用旧版应用入口、主题初始化和独立任务状态。
4. 每迁移一个区域，保留回退开关并进行亮/暗主题和任务恢复测试。

验收：剧本工作室不再依赖旧版主题初始化；任务中心数据来自统一服务；页面切换不销毁任务。

### 阶段四：替换工作室迁移

1. 将人物检测、关键帧分析、视频生成拆为统一任务阶段。
2. 抽离 `OriginalReplacementWorkspace` 中的宿主适配和业务执行逻辑。
3. 用 React 工作区替换旧版挂载器，复用现有 IPC/API 服务。
4. 迁移完成后删除旧版替换工作室入口和专用主题覆盖。

验收：替换工作室和资源管理使用同一外壳、导航、主题和任务中心；失败原因可追溯。

### 阶段五：清理旧版兼容层

仅在阶段三、四验收通过后执行：

- 删除旧版主题事件桥和未使用的主题预设入口。
- 删除旧版工作室挂载入口和重复任务状态。
- 清理只服务旧版工作室的背景 CSS、变量和适配代码。
- 更新测试、文档和构建入口。

## 6. 关键技术约束

- 任务执行器必须运行在页面生命周期之外，页面只订阅状态。
- 取消操作必须显式、幂等，并记录取消时间和取消来源。
- 任务状态更新需要带版本号或序列号，防止旧页面回写覆盖新状态。
- 主题令牌禁止在模块 CSS 中重新定义主应用亮暗颜色。
- 旧版 API 可以暂时保留，但必须通过服务适配层调用，不能继续创建第二套 UI 状态。
- 迁移期间不删除仍被生产路径引用的旧代码。

## 7. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 一次性重写导致剧本功能回归 | 分区域迁移，保留旧版回退开关 |
| 旧版任务无法被统一取消 | 先定义执行器能力和取消边界；不支持取消的任务显示明确提示 |
| 长任务跨页面丢失 | 任务状态持久化，执行器放在宿主层 |
| 主题令牌覆盖顺序冲突 | 统一入口加载顺序，并增加亮/暗主题快照测试 |
| 历史项目数据格式不兼容 | 增加版本化迁移，不直接改写原始项目文件 |

## 8. 验收清单

- [ ] 应用只有一个可见主题设置入口。
- [ ] 资源管理、剧本、替换、媒体工具亮色和暗色视觉一致。
- [ ] 切换页面不会自动取消任务。
- [ ] 剧本工作室内可以查看统一任务中心的过滤视图。
- [ ] 每条任务可以查看成功、失败、取消和中断状态。
- [ ] 失败任务显示可理解的失败原因和技术详情。
- [ ] 可查看总耗时及各阶段耗时。
- [ ] 支持取消、重试、删除任务记录。
- [ ] 应用重启后可恢复历史任务记录。
- [ ] 剧本和替换工作室最终不再依赖旧版独立主题和工作室入口。
