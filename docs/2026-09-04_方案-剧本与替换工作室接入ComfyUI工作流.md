# 剧本与替换工作室接入 ComfyUI 工作流方案

## 1. 文档目的

本方案解决当前剧本工作室、替换工作室的图像、视频生成主要依赖云端 API，而项目已经具备本地 ComfyUI 工作流和生成模块的问题。

本轮只提交方案文档，不修改业务代码。方案经审核确认后，再按阶段实施，并在每个阶段完成可回退验证。

## 2. 结论摘要

建议把 ComfyUI 工作流作为云端 API 之外的第二种媒体生成后端，统一接入图像、视频和音频生成链路：

```mermaid
flowchart LR
    A[剧本工作室 / 替换工作室] --> B[统一媒体生成服务]
    B --> C{backend}
    C -->|cloud-api| D[现有 cloud-images / cloud-videos / cloud-audios]
    C -->|comfyui-workflow| E[工作流解析与执行器]
    C -->|indextts| F[现有 IndexTTS 声音克隆]
    E --> G[ComfyUI /prompt]
    G --> H[/history 轮询]
    H --> I[结果归档与资源记录]
    D --> I
    F --> I
```

核心原则：

1. 复用现有 `workflows.js`、ComfyUI 适配器和任务持久化能力，不再为两个工作室各写一套 ComfyUI 调用逻辑。
2. 页面只提交生成请求和订阅任务，工作流执行必须位于宿主层，页面切换不能中断任务。
3. 云端 API、ComfyUI 工作流、IndexTTS 是可明确区分的后端；ComfyUI 失败时不静默回退到 API。
4. 生成结果统一转换为本地 `outputPath`，并写入工作台项目目录，保证资源管理和后续替换、剪辑链路可以继续使用。

## 4. 改造目标与范围

### 4.1 本次目标

- 剧本工作室支持图像和视频通过 ComfyUI 工作流生成。
- 替换工作室支持角色图、替换图和替换视频通过 ComfyUI 工作流生成。
- 为音频生成预留同一套后端接口，并接入已有音频工作流；现有 IndexTTS 保持可用。
- 工作流参数、参考素材、模型文件和输出结果可以被任务中心、资源管理和项目数据追溯。
- 支持单个生成、批量生成、取消、失败重试和页面切换后继续运行。

### 4.2 暂不纳入本阶段

- 不重写 ComfyUI 节点编辑器。
- 不自动安装第三方自定义节点；只提供缺失节点的可读诊断。
- 不把所有旧版 ShuoCanvas 页面一次性迁移为 React。
- 不删除现有云端 API、IndexTTS 或旧版工作流入口。

## 5. 建议的统一接口

### 5.1 生成请求

在宿主层建立统一的媒体生成请求，工作室只负责组装业务字段：

```ts
type MediaKind = 'image' | 'video' | 'audio';
type GenerationBackend = 'cloud-api' | 'comfyui-workflow' | 'indextts';

interface MediaGenerationRequest {
  module: 'story' | 'replacement';
  projectId: string;
  taskType: string;
  assetId?: string;
  kind: MediaKind;
  backend: GenerationBackend;
  prompt?: string;
  input?: string;
  references?: Array<{
    path: string;
    kind: 'image' | 'video' | 'audio';
  }>;
  workflowPath?: string;
  workflowParams?: Record<string, unknown>;
  modelFiles?: Record<string, string>;
  projectSubdir: string;
  metadata?: Record<string, unknown>;
}
```

统一结果契约：

```ts
interface MediaGenerationResult {
  id: string;
  kind: MediaKind;
  outputPath: string;
  outputUrl?: string;
  outputPaths?: string[];
  backend: GenerationBackend;
  taskId?: string;
  metadata?: Record<string, unknown>;
}
```

### 5.2 宿主桥

在 `Serpent/src/preload/index.ts` 的 hosted bridge 中增加以下能力，并加入 `HOST_INVOKE_CHANNELS` 白名单：

```text
workflows:list
workflows:inspect
workflows:validate
workflows:run
workflows:cancel
```

同时增加工作流任务事件订阅，复用主进程现有的 `tasks:update` 事件。桥接层不暴露 ComfyUI 内部 HTTP 细节，渲染层只接收任务状态和统一结果。

建议接口形态：

```ts
host.workflows.list()
host.workflows.inspect(path)
host.workflows.validate(path)
host.workflows.run(request)
host.workflows.cancel(taskId)
host.tasks.onUpdate(listener)
```

如果 hosted 运行模式的主进程尚未注册对应 IPC，则先在宿主主进程增加转发；不得让渲染器直接绕过桥接访问本机文件或 ComfyUI 端口。

## 6. 工作流配置与参数绑定

### 6.1 项目配置

工作室项目保存生成后端配置，采用版本化结构，旧项目缺省按云端 API 处理：

```ts
interface GenerationProfile {
  backend: GenerationBackend;
  workflowPath?: string;
  workflowParams?: Record<string, unknown>;
  modelFiles?: Record<string, string>;
  inputBindings?: Record<string, string>;
  outputNodes?: string[];
}

interface StudioGenerationConfig {
  schemaVersion: 1;
  image?: GenerationProfile;
  video?: GenerationProfile;
  audio?: GenerationProfile;
}
```

配置建议挂在项目的 `generation` 节点下，不写入全局设置；全局设置只保存 ComfyUI 安装目录、远程地址和默认工作流目录。

### 6.2 槽位绑定规则

1. 选择工作流后调用 `inspect`，展示工作流类型、节点数、可识别的 prompt/尺寸/时长/种子/模型/素材/输出槽位。
2. 对可自动识别的槽位使用现有 `applyOverrides`、`assignUploadedFiles` 和模型重映射逻辑。
3. 节点命名不统一时，允许用户在“工作流参数”面板手动指定绑定；不能只硬编码 `image`、`video`、`audio` 这几个名字。
4. 参考图、源视频、音频等输入统一转换为 `references`，由执行器上传并回填到工作流输入节点。
5. 输出节点可返回多种媒体时，按 `kind` 过滤；若没有匹配输出，任务失败并提示“工作流未产生目标类型输出”。

### 6.3 工作流来源

第一阶段支持：

- 已配置 ComfyUI 安装目录下的 `user/default/workflows`。
- 用户通过工作流选择器指定的 JSON 文件。

后续可支持远程 ComfyUI，但必须复用现有的地址白名单、上传和结果下载策略，并在设置中明确显示“本机 / 远程”来源。

## 7. 任务与并发策略

### 7.1 任务元数据

在现有任务记录基础上补充：

| 字段 | 说明 |
| --- | --- |
| `module` | `story` 或 `replacement` |
| `projectId` | 工作室项目 ID |
| `taskType` | 角色图、分镜图、替换视频等业务类型 |
| `assetId` | 分镜、角色或替换镜头 ID |
| `backend` | `cloud-api`、`comfyui-workflow`、`indextts` |
| `workflowPath` | 实际使用的工作流路径 |
| `workflowName` | 展示用名称 |
| `inputPaths` | 参考素材路径摘要 |
| `outputPaths` | 一个或多个生成结果 |
| `errorCode/errorMessage` | 可读错误和技术详情 |

### 7.2 队列策略

建议默认采用“ComfyUI 单实例串行执行，跨后端并行”：

- 同一 ComfyUI 实例的工作流任务进入队列，避免显存争用和当前单任务限制。
- 云端 API 任务可以按现有策略并行，不受 ComfyUI 队列阻塞。
- 后续如确认存在多 GPU 或多实例，再把并发度抽象为配置项。
- 用户提交批量任务时，立即返回多个排队任务，而不是第二个任务直接报“已有任务在运行”。

取消必须同时处理应用任务记录和 ComfyUI 队列：先删除队列项，再发送 interrupt，最后将任务置为 `cancelled`；重复取消应保持幂等。

## 8. 输出归档与资源管理

所有后端都返回统一本地路径，并沿用工作台项目分级目录：

```text
输出根/
├─ 剧本工作室/<项目ID>/图像/
├─ 剧本工作室/<项目ID>/视频/
├─ 剧本工作室/<项目ID>/音频/
├─ 替换工作室/<项目ID>/图像/
├─ 替换工作室/<项目ID>/视频/
└─ 替换工作室/<项目ID>/音频/
```

归档规则：

- 图片、视频、音频分别按目标类型落盘。
- 工作流产生多个结果时保留 `outputPaths`，主结果写入 `outputPath`。
- 生成记录必须带项目、资产和任务 ID，资源库可以从路径反查来源。
- 预览输出仅在没有正式保存输出时作为回退；不能把临时目录路径直接当作最终项目资源。
- 输出文件名不得直接使用未清洗的模型名、工作流名或用户输入。

## 9. 用户界面方案

### 9.1 生成入口

在剧本工作室和替换工作室的生成设置中，为每种媒体显示后端选择：

| 媒体 | 可选后端 |
| --- | --- |
| 图像 | 云端 API、ComfyUI 工作流 |
| 视频 | 云端 API、ComfyUI 工作流 |
| 音频 | 云端 API、ComfyUI 工作流、IndexTTS（按现有能力显示） |

默认值：历史项目保持原来的云端 API；新项目沿用全局默认，不自动切换到 ComfyUI。

### 9.2 工作流设置面板

选择 `ComfyUI 工作流` 后显示：

- 工作流选择器和来源（本机/远程）。
- “检查工作流”结果：节点数量、缺失自定义节点、可绑定输入和输出。
- 业务字段到工作流槽位的绑定状态。
- 高级参数折叠区：种子、尺寸、时长、步数、CFG、模型文件和文本覆盖。
- 参考素材映射和缺失输入提示。

工作室主卡片只展示后端、工作流名和任务状态，不把所有 ComfyUI 节点参数铺在主界面。

### 9.3 结果与错误

- 任务运行中显示排队/执行状态、进度和当前工作流。
- 成功后显示统一预览、打开所在文件夹和重新生成。
- 失败时显示明确原因，例如缺少自定义节点、输入槽位未绑定、模型文件不存在、ComfyUI 连接失败、没有目标类型输出。
- 不自动切换到云端 API；用户点击“改用云端 API 重试”时才建立新任务。

## 10. 分阶段实施计划

### 阶段一：确认契约与只读能力

1. 固化 `MediaGenerationRequest/Result`、任务元数据和项目配置版本。
2. 盘点剧本、替换工作室实际使用的生成函数和结果字段。
3. 为工作流选择器增加 list/inspect/validate 的 hosted 转发和只读 UI。
4. 增加工作流类型、输入输出槽位和缺失节点的诊断展示。

验收：两个工作室可以选择并检查工作流，但尚不改变生成行为；旧项目和云端 API 行为不变。

### 阶段二：统一宿主执行层

1. 将 `workflows:run/cancel` 接入 hosted bridge。
2. 把当前 `runCustomWorkflowTask` 的单任务拒绝改为队列调度，保留 ComfyUI 单实例串行默认策略。
3. 抽取统一结果归一化、输出类型过滤和项目目录归档逻辑。
4. 给任务记录补充 `module/projectId/taskType/assetId/backend/workflowPath`。

验收：通过测试请求可以提交 image/video/audio 三类工作流，任务可排队、取消、失败和恢复，结果有本地 `outputPath`。

### 阶段三：剧本工作室接入

1. 将角色图、分镜图生成改为统一媒体服务分派。
2. 将分镜视频生成改为统一媒体服务分派。
3. 维持现有剧本项目、分集、分镜数据结构，只增加生成配置和任务关联。
4. 支持单个和批量生成，批量任务按资产 ID 回写结果。

验收：同一分镜可以在云端 API 与 ComfyUI 工作流之间切换；生成结果预览、重试、资源归档和后续编辑不回归。

### 阶段四：替换工作室接入

1. 将角色参考图、替换图接入统一工作流分派。
2. 将替换视频接入统一工作流分派，保留现有参考视频/音频输入。
3. 统一 `StudioProductionStep` 的结果归一化和任务状态显示。
4. 保留现有人物检测、素材提取、IndexTTS 和成片合成链路。

验收：替换图和替换视频可以使用 ComfyUI；云端、ComfyUI、IndexTTS 三类后端的结果都能进入同一项目资源目录。

### 阶段五：音频工作流与高级绑定

1. 接入已有音频工作流，覆盖 TTS、音色设计或音乐生成等已存在流程。
2. 完善 audio 输入上传、输出类型过滤和音频预览。
3. 支持工作流参数模板、模型文件选择和按项目保存。
4. 对工作流缺少正式保存节点的情况，明确允许使用预览输出或要求用户补充保存节点。

验收：音频工作流生成结果可播放、可归档、可被成片流水线引用；IndexTTS 仍可独立使用。

### 阶段六：测试、文档与灰度开关

1. 增加 API、IPC、任务队列、槽位映射和输出归档测试。
2. 对本机无 ComfyUI、远程地址不可达、缺失自定义节点、模型缺失和任务中断做故障测试。
3. 增加工作室级灰度开关，按项目启用 ComfyUI，便于回退。
4. 更新用户帮助和工作流编写约定。

验收：可以按项目关闭 ComfyUI 功能并恢复云端 API；升级旧项目不会丢失生成配置或历史资源。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 工作流依赖未安装的自定义节点 | `validate/inspect` 阶段提前报告节点名；执行失败展示安装提示和节点错误 |
| 节点命名和输入结构不统一 | 槽位启发式识别 + 手动绑定；绑定结果随项目保存 |
| 工作流输出同时包含图片、视频、音频 | 根据 `kind` 和 `outputNodes` 过滤；没有匹配结果则失败，不误写入错误资产类型 |
| ComfyUI 显存不足或长时间占用 | 默认单实例串行队列；任务中心显示排队状态；支持显式取消 |
| 页面刷新造成结果丢失 | 任务状态和结果路径持久化到宿主层，页面仅订阅 |
| 本地路径被恶意或错误输入穿越 | 工作流路径、参考素材和输出目录做根目录校验；输出文件名统一清洗 |
| 云端 API 与 ComfyUI 结果字段不一致 | 统一 `MediaGenerationResult`，工作室不读取后端私有字段 |
| 直接复用旧版适配器导致宿主边界混乱 | 适配器负责参数/结果转换，IPC 和任务生命周期由宿主统一负责 |

## 12. 需要审核确认的决策

请重点确认以下事项，确认后再进入代码修改：

1. 是否采用“云端 API + ComfyUI 工作流 + IndexTTS”三种后端并存的方案。
2. ComfyUI 第一阶段是否只支持本机安装目录，还是同时支持已配置的远程 ComfyUI 地址。
3. 工作流选择是“按项目保存一套图像/视频/音频配置”，还是允许每个角色、分镜、镜头单独覆盖。
4. 是否接受同一 ComfyUI 实例默认串行，批量任务进入队列的策略。
5. 音频工作流是否在图像、视频完成后再接入，IndexTTS 是否继续作为独立后端保留。
6. 是否允许为现有项目增加 `generation.schemaVersion` 和生成后端字段，并对旧项目自动补默认值。

## 13. 建议的审核回复

如无修改，可回复：

> 确认按本文档实施；第一阶段先支持本机 ComfyUI，采用项目级图像/视频/音频配置，同一实例串行排队，保留云端 API 和 IndexTTS，音频工作流放到后续阶段。

如需调整，请直接指出需要修改的章节或决策项；在收到确认前不修改业务代码。
